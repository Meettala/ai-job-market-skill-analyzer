## Product purpose

The application analyses a defined synthetic or explicitly permitted posting dataset, extracts skills, stores postings and extracted skills in SQLite, calculates deterministic frequency/co-occurrence statistics, compares literal entered skill labels with recurring extracted terms, exports JSON and presents the result in Streamlit.

The public repository does **not** claim real-time or representative labour-market demand, UK-wide prevalence, hiring likelihood, ATS scoring or verified candidate capability.

## Data and reporting truth

- `data/sample_postings.json` is synthetic and generated by `data/generate_sample_postings.py`.
- The generator uses a fixed local RNG and supports `python data/generate_sample_postings.py --check` for byte-for-byte verification.
- Posting frequency uses the true SQLite posting count as the denominator.
- Skill frequency uses `COUNT(DISTINCT posting_id)`, so repeated mentions within one posting do not inflate posting-level frequency.
- `gap_report()` is an internal function name. Public wording should call the output an entered-skill comparison and explain that it is literal, dataset-scoped and not a capability/hiring score.

## Extraction truth

The active deterministic extractor in `src/analyzer/extractor.py` consumes the curated AI/ML taxonomy in `src/analyzer/taxonomy.py`. It is intentionally narrow and testable.

The bundled ESCO artefact in `data/esco-vocabulary.json.gz` is a **reference/lookup vocabulary**, not the active default extractor. `src/analyzer/esco_vocabulary.py` validates the committed artefact, exposes attribution/scope information and provides exact surface-form lookup that can return multiple concept URIs for ambiguous labels.

Do not claim all-job-domain extraction merely because ESCO is bundled.

## Optional provider boundary

Provider calls require both:

```text
ENABLE_PROVIDER_MODE=true
```

and either `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`.

A key alone must not change the extraction path. When provider mode is enabled, posting text is sent to the configured provider after delimiter escaping. Provider output must be a bounded JSON list containing exactly `skill`, `category` and `evidence` string fields; duplicates are removed. Provider failures/invalid output fall back to deterministic results with a generic warning, and provider output is never executed.

## SQLite and pipeline trust model

- writes are parameterised;
- foreign keys are enabled;
- `(posting_id, skill)` is unique;
- input postings are validated as a non-empty JSON array of objects;
- pipeline DB connections are closed in `finally`;
- JSON export is deterministic for deterministic input/mode;
- no provider credentials are required for the normal pipeline or test suite.
